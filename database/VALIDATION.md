# Проверка компонента БД

Ниже приведены дополнительные проверки в среде разработки. Результаты на компьютере
участника приведены после этого протокола.

| Компонент | Версия |
| --- | --- |
| PostgreSQL | 16.2 |
| Python | 3.12.14 |
| SQLAlchemy | 2.1.9 |
| Alembic | 1.20.1 |
| Psycopg | 3.3.9 |
| pytest | 9.2.0 |

Миграции выполнялись под владельцем тестовой базы `pasis_user` без SUPERUSER,
CREATEDB и CREATEROLE.

Результаты:

- Создание схемы из пустой базы: успешно.
- Текущая ревизия: `0002_rbac_seed (head)`.
- Сверка миграций с ORM: `No new upgrade operations detected.`
- `pytest tests/database -q`: **23 passed**.
- Повторный `upgrade head`: без дублирования данных.
- `downgrade base` и повторный `upgrade head` на одноразовой тестовой БД: успешно.
- Создание локальной конфигурации, специальные символы в пароле и защита существующего `.env`
  от перезаписи: успешно.
- Генерация SQL через `alembic upgrade head --sql`: успешно.

После миграций: users = 0, roles = 3, permissions = 4, user_roles = 0,
role_permissions = 7. Тестовые пользователи не входят в начальные данные.

На компьютере участника подтверждены подключение к PostgreSQL 18.6, импорт библиотек
из Python 3.15.0 и успешное применение обеих миграций до `0002_rbac_seed (head)`.
Проверены количества записей (0, 3, 4, 0, 7) и наборы прав всех трёх ролей.
Фактические скриншоты подключения, миграций и просмотра таблиц сохранены в `database/report/`.
На компьютере участника в отдельной базе `pasis_db_test` успешно выполнен pytest:
**23 passed in 0.46s**. Скриншот сохранён как `database/report/04_database_tests.png`.

Дополнительно проверена конфигурация Docker:

- Docker Compose v5.6.0 успешно разобрал `docker-compose.yml`.
- Проверены параметры сервисов, зависимость от healthcheck, порт 5433, том PostgreSQL 18
  и передача приложению его учётных данных без пароля администратора.
- Проверены первичная подготовка `.env`, повторный запуск без смены сгенерированных паролей
  и сохранение существующих настроек локальной БД.
- SQL инициализации контейнера выполнен на тестовом PostgreSQL: проверены владелец базы,
  отсутствие административных прав у пользователя, SCRAM-аутентификация, отказ при неверном
  пароле и применение миграций под созданным пользователем.
- Полный запуск Docker Engine, сборка образа и запуск контейнеров здесь не выполнялись.
  Этот этап подтверждается командой при сборке приложения в среде с Docker.
